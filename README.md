# Basket cross-sell

Рекомендації товарів до кошика на даних Instacart: popularity, co-occurrence (conditional, cosine, lift) і EASE.

## Структура
- `scripts/` - підготовка даних і навчання/оцінювання моделей
- `notebooks/` - EDA і 5 прикладів кошиків
- `src/` - код моделей, метрик і завантаження даних
- `app/dashboard.py` - дашборд
- `NOTES.md` - рішення, експерименти і результати

## Запуск
1. Створити середовище, активувати його і встановити залежності (Python 3.12):
   ```
   python -m venv .venv
   .venv\Scripts\activate          # Linux/macOS: source .venv/bin/activate
   pip install -r requirements.txt
   ```
   Усі наступні команди виконуються в активованому середовищі.
2. Завантажити дані з https://www.kaggle.com/datasets/psparks/instacart-market-basket-analysis і розпакувати csv у `data/raw/`
3. Виконати ноутбуки по черзі (в IDE або з консолі, з папки ноутбука, бо шляхи в ноутбуках відносні):
   ```
   cd scripts
   jupyter nbconvert --to notebook --execute --inplace prepare_data.ipynb
   jupyter nbconvert --to notebook --execute --inplace evaluate.ipynb
   cd ..
   ```
   - `prepare_data.ipynb` - семпл і поділ train/val/test -> `data/processed/`
   - `evaluate.ipynb` - підбір параметрів, метрики на test, збереження моделей -> `artifacts/` (~40 хв)
   - `notebooks/eda.ipynb`, `notebooks/examples.ipynb` - за бажанням
4. Дашборд (з кореня проєкту):
   ```
   streamlit run app/dashboard.py
   ```

Seed: 47 для семплу і поділу (`prepare_data.ipynb`), 42 для вибору прикладів.

## Протокол оцінювання
- Семпл 100 тис. замовлень, поділ за користувачами: train 72% / val 8% / test 20%. Параметри підбираємо на val, фінальні цифри на test. Усі статистики рахуються лише на train.
- Каталог кандидатів: товари з 5+ появами в train (14 603 товари). Покриття прихованих товарів test каталогом 93.4%. Товари поза каталогом лишаються в знаменнику Recall.
- Видимі = перші floor(n/2) товарів за `add_to_cart_order`, приховані = решта. Лише кошики з 2+ товарами, 18 771 тестовий кошик.
- **Recall@10** = частка прихованих товарів, що потрапили в топ-10.
- **NDCG@10** = те саме, але з урахуванням позиції: влучання вгорі списку важить більше. Бінарна релевантність, нормуємо на ідеальний порядок.

## Результати (test)

| Модель | Recall@10 | NDCG@10 |
|---|---|---|
| popularity (baseline) | 0.0637 | 0.0563 |
| conditional, min_support 3 | 0.0841 | 0.0734 |
| cosine, min_support 5 | 0.0835 | 0.0733 |
| lift, min_support 100 | 0.0613 | 0.0539 |
| **EASE, λ=1000** | **0.0852** | **0.0759** |

Варіанти з урахуванням порядку додавання (`ordered`) гірші для всіх нормалізацій, деталі в `NOTES.md`.

Фінальна модель **EASE**: найкраща за обома метриками (+34% Recall і +35% NDCG до baseline). Вона враховує весь кошик разом, а не суму незалежних пар, і менше за conditional тягне найпопулярніші товари. conditional майже не поступається і значно простіший, тож годиться як запасний варіант.

5 прикладів кошиків з рекомендаціями всіх моделей: `notebooks/examples.ipynb`.

## recommend(basket, model_name, k=10)
`src/models/recommend.py`. Повертає position, product_id, product_name, aisle, score.
- Товари з кошика не рекомендуються, дублікатів немає.
- Порожній кошик: популярні товари.
- Невідомі й рідкісні товари (поза каталогом) ігноруються. Якщо сусідів менше ніж k, список доповнюється популярними товарами зі score 0.
- Score не є ймовірністю і порівнюваний лише в межах однієї моделі:
  - popularity: у скількох кошиках train є товар
  - conditional: сума P(товар | товар кошика) по товарах кошика
  - cosine: сума косинусних схожостей з товарами кошика
  - EASE: сума ваг лінійної регресії від товарів кошика

## A/B-тест
- Основна метрика: середня вартість замовлення (або кількість товарів у замовленні) у групі з рекомендаціями проти контрольної.
- Показник небажаного ефекту: конверсія кошика в оформлене замовлення. Якщо блок рекомендацій відволікає чи дратує, вона впаде. Також варто стежити, чи не падають продажі товарів з тієї ж полиці (рекомендації-замінники забирають покупки, а не додають).

## Припущення й обмеження
- Протокол "вгадай приховану половину" винагороджує популярні товари і не доводить зростання продажів. Товари з одного чека не завжди є доповненнями.
- Частина рекомендацій є замінниками (інші смаки того ж товару), моделі їх не відрізняють від доповнень.
- Історію покупок користувача не враховуємо, хоча 59% покупок у даних повторні.
- Рідкісні товари (<5 появ у train) не рекомендуються зовсім, ~6.6% прихованих товарів недосяжні.
- EASE тримає щільну матрицю 14.6k x 14.6k (~2.5 ГБ пам'яті при навчанні), на сотні тисяч товарів так не масштабується.
- Дані з Kaggle-дзеркала оригінального датасету Instacart. Семпл ~1.5 замовлення на користувача.

## Наступні кроки
1. Враховувати історію користувача: не рекомендувати те, що він і так регулярно купує (це не збільшить чек).
2. Відсіювати замінники, наприклад штрафувати товари з тієї ж полиці, що й товари кошика.
3. Embeddings (item2vec або ALS), щоб краще працювати з рідкісними товарами.
